## 4. Expected vs Actual

- 预期: clean baseline 全绿。  
  实际: 测试全绿，但 checkpoint/stale CI 初始失败。
- 预期: stale 可通过上下文刷新收敛。  
  实际: `finish --sync-context` 后 `stale --ci` 由 FAIL 收敛到 PASS。

  实际: inspect/migrate dry-run 均显示 `writes_files: false`。

## 5. Issues Found

- Issue A（门禁阻断）: `checkpoint --ci` 被 `possible_semantic_drift` 与 `untracked_function` 阻断。
- Issue B（初始噪音）: 上下文未同步时，`stale --ci` 直接 FAIL，需额外执行 `finish --sync-context`。
- Issue C（流程摩擦）: `finish --sync-context` 输出 `harbor log/accept` 建议，可能让新用户误解为必须执行。

## 6. False Positives

- 候选 FP-1: `possible_semantic_drift` 原因包含“函数缺少 Docstring 契约”，需要人工复核其是否真 drift。
- 候选 FP-2: `untracked_function` 对新增测试函数直接阻断，可能在“内部低风险变更”场景偏保守。

## 7. False Negatives

- 本轮未观察到明显 FN。
- 但因未执行 S3/S4/S5（CLI/JSON/write target 扰动），无法完成高风险契约漏报验证。

## 8. Workflow Friction

- 开发者需理解两套门禁语义:
  - `stale/doctor` 偏“上下文与健康”
  - `checkpoint` 偏“语义漂移与变更跟踪”
- 在当前仓库状态下:
  - `stale` 可被 `finish --sync-context` 收敛
  - `checkpoint` 仍要求处理 drift/untracked，不会被 context sync 自动消除
- 这符合“不可用 accept 掩盖漂移”的原则，但对首轮使用者有认知成本。
